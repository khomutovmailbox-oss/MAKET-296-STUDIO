# VectorForge Pro: плиточный кэш предпросмотра

В рабочем архиве исходников: `studio/fx_compositor.py` (рендер прямоугольной области), `studio/tile_cache.py` (плитки, LRU), интеграция в `studio/studio.py`, тесты и снимок реального окна. **В GitHub на текущем этапе загружен только модуль `studio/tile_cache.py`**, прочие файлы нужно перенести из ZIP в папку `projects/vectorforge-pro/` той же ветки.

## Что изменено
- Средняя кнопка мыши перемещает увеличенную страницу.
- Рендерятся только видимые плитки 256×256 RGBA; бюджет LRU 32 MiB.
- На краю плитки используется 4 px дополнительного контекста — отсутствие швов Cairo/Bezier.
- Очень большие масштабированные PNG-маски обрабатываются по ROI без выделения полного гигантского альфа-растра.
- При изменении документа, страницы или масштаба плиточный кэш не переиспользуется.
- Неподдерживаемые SVG эффекты явно перенаправляются во внешний рендерер либо сообщают ошибку.

## Контроль
- 37 тестов Python редактора, 34 теста экспериментального импорта, 6 тестов настоящего Tk-окна.
- Новые 6 тестов плиток прошли после распаковки ZIP в чистую папку.
- Результат RGBA-плиток на M16 тест-макете 1000×700 совпал с полным рендером пиксель-в-пиксель.
- Новый процесс `vforge_live_editor` собран из текущей исходной копии. Полная новая сборка всех C++ тестовых бинарников не завершена. 16 CTest пройдены на прежнем неизменённом C++-ядре M16.

## Замер композитинга (Linux)
| Операция | Медиана |
|---|---:|
| Полная страница 1000×700 | 169,425 мс |
| Первый viewport 500×400 | 172,841 мс |
| Сдвиг внутри уже рассчитанных плиток | 0,153 мс |
| Сдвиг с двумя новыми плитками | 43,960 мс |
| Повтор того же viewport | 0,082 мс |

Время включает **только CPU-композитинг**, не экспорт SVG/C++ IPC/Tk/отрисовку. Первый кадр не ускорился. GPU/Windows/полный CDR-AI импорт не реализованы.
